Echidna

The agent's face on this LAN. Not a chatbot bolted onto the Menu — the same agent you would meet in a terminal, written down, with Easy Mode beside it.

Same agent, both audiences. An experienced operator keeps a terminal session open and will never open this page. A new operator will never open a terminal and will only see this. Both must reach the same tools, the same book of jobs and the same state — so this page grows by adding panels, never by capping what it can do.

What it is

A Hydra V2 door on :8138. Its own module, because the conversation outlives the Menu window: the Menu displays it, it does not contain it.

PaneWhat it does
TalkThe thread, oldest first: what you said, what it answered, how long it took, which agent session answered it. Failed asks are turns too, marked as failures.
Easy ModeOne big question with tappable answers; a declared list of launch buttons; media (image, audio, video) from what we made; and the honest state of speech.

The board (top half)

A news caster's screen behind him: one card, replaced in place, never scrolled. It shows the current question while the agent works, then the answer; goals and outputs can be put there too. A back button walks the few cards that were replaced — a stack of one-line memories, not a feed. The bar between the board and the talk is a real drag handle (keyboard: focus it and use ↑/↓), and its position is remembered.

The same conversation on every node

The conversation is published to State as node.<ref>.echidna — thread and board in one branch, written by the one node that hosts the agent. Every other node's pane reads that branch through its Mirror (GET /api/conversation?host=<ref>), so two nodes cannot disagree about what was said. A viewer says hosted on 123 and its composer is disabled instead of pretending to be local.

How it answers

It shells out to the real agent — hermes chat --query-file … --oneshot -Q --format stream-json — with a timeout it cannot hang past, and keeps the session id so the next ask continues the same conversation. The binary it will run is reported in the pane's status chip before you ask, so a missing agent is visible rather than discovered as silence.

The answer arrives while it is being written: the agent's text deltas are forwarded to the pane as server-sent events, so the bubble grows word by word instead of holding a spinner. The final turn is built from the agent's own result line, which is also what lands in thread.jsonl — the stream and the history are the same answer, not two versions of it.

One ask at a time. A second ask while one is running is refused with a reason, not queued behind a spinner.

Easy Mode is a declaration

Everything tappable is written in data/easy.json first: the question, its options, the launch actions, the media, and which LAN speech services exist. The pane never invents an action, and it says what is missing ("no speech service declared on this LAN") instead of hiding the capability.

Speech is optional, never mandatory

Speech-to-text and text-to-speech are declared services elsewhere on the LAN. With a listening service declared, a push-to-talk button appears. Without one, there is no microphone — not a broken one. Text always works.

Personality

Echidna follows the Prime Directive and will not take on a malicious project. A request to harm, deceive or extract from someone is refused in the conversation, not quietly obeyed.

Files and endpoints

PathWhat
data/thread.jsonlThe conversation, append-only. The only durable thing here.
data/easy.jsonThe Easy Mode declaration.
data/agent.jsonThe agent session being continued.
data/prompts/One file per ask, kept as evidence of what was actually sent.
GET /api/stateThread, Easy Mode, agent status.
POST /api/say{"text":"…"} → asks once, returns the two turns it wrote.
POST /api/say/streamThe same ask as server-sent events: turn (the question on the record), delta (words in flight), meta (token counts), done (the published turn), fail. A : comment every 10 s keeps a quiet connection alive.

Honest limits today

  • The talk pane asks a fresh agent process per message. It continues the same session, but it is not a long-lived process yet.
  • Speech is declared and displayed, not wired: no STT or TTS service is declared on this LAN yet.
  • Launch buttons open pages; a button that would run a command is shown as not wired until the action runner exists.
