Access

run a command line on a node and read the console back · door on :8143 · the executing half is the EchidnaAccess agent on each node's :8142

The operator's ask, in his words: an app that accepts a command line, runs it elevated, and returns console out — with no middle man. Access is the door for that. You pick a node, type a line, and get stdout, stderr and the real exit code back from an agent running on that machine. One install per node, ever; after that no UAC prompt and nobody at a keyboard.

The door itself holds no privilege. It cannot elevate anything on its own — it only talks to an agent that already has the privilege. That separation is the whole design: a door that could elevate by itself would be a second, silent way into every machine on the LAN.

A command line, exactly as typed

The agent wraps the line in powershell -EncodedCommand ($ProgressPreference='SilentlyContinue' prepended), so quotes, pipes and $ survive the trip without escaping. Working directory defaults to %SystemRoot%. The child is killed as a tree on timeout and the result comes back with exitCode: 124 — a timeout is a fact, not a hang.

Open by default, and why that is still gated

The operator asked for no auth: a command line in, console out, no questions. So the agent has no token unless token.txt exists — in which case it is required. What remains is not ceremony: an allow.json client list and a firewall rule written by the installer, both narrowed to the controller (192.168.1.123). "Open" therefore means open to one address, not to the LAN, and every call — including every refusal — is appended to audit.jsonl on the node that ran it.
