Electron_Wrapper

Module docs — the ONE file. Purpose + the contract (.d.ts) of every file. Generated by npm run docs — edit the sources, not this file.

Purpose

Electron_Wrapper is THE GENERIC ELECTRON SHELL: a template + registered tabs. Hand it a template (spot(s) for tab insertions — "where tabs go and how to render") and register tabs ({name, path}: the path is an ADDRESS, and the wrapper maps each tab as a div/iframe to its page); register menus (label -> function, nested, with separators); wire an event-handler instance and every tab click, menu click, tab close and the app's own close ("app closed") goes OUT as an event through it.

It ships WITH an app tray — default ON, icon as input, a menu tree with matching onclick. Point it at a State door and each tab's state is PULLED and mirrored: solid (silent default) · highlighted · flashing, and a lone flashing tab auto-selects. The module wraps; it decides nothing; it is CONTENT-BLIND — what a tab renders (ComfyUI, anything) is nobody's business. The compiled app never needs updating: tabs and menus are registered after run start, added and popped as life goes on. Closing a tab informs the handler and pops it; registering it again brings it back.

The Golden Layout dialect lives ONLY in public/ts/renderer/app.ts — the neutral arrangement is plain data, so the layout library under the wrapper stays swappable. Generic — for all projects; no project words inside. Embed it: the ONE FILE another code thread loads is Electron_Wrapper_module.js at the module root — createModule() stands the wrapper up in the host's thread (pass the electron surface, or run inside a real app). npm run demo is the other life: a hand-runnable dumb terminal fed by demo/template.json — edit the addresses, run, done.

Run it

npm test               # the gate: build → typecheck → selftest
npm run demo           # the demo app (needs an electron binary; see README)
node Electron_Wrapper_module.js   # the embed entry's own check
