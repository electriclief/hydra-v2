VideoIn

door on port 8162

Serves the camera as an MJPEG stream for browsers and as single JPEG snapshots, from a local DirectShow webcam or an ipwebcam-style URL. Each viewer gets its own ffmpeg child that dies with the connection, so an abandoned tab never keeps the camera busy.

Concepts

MJPEG because it always plays

multipart/x-mixed-replace with one complete JPEG per frame: any browser, any VLC, no negotiation. A dropped connection costs one frame.

Per-viewer process

ffmpeg is spawned for each subscriber and killed on close, so the camera is never held open by an abandoned tab.

URL sources are handed over

An ipwebcam URL is already a stream, so /api/video answers 302 to it rather than transcoding for no reason.

    Wiring
  • needs: ffmpeg.exe
  • gives: GET /api/devices, GET /api/snapshot (image/jpeg), GET /api/video (MJPEG)
