# Event_Handler

A GENERIC event handler. Register events, **trigger** them (fire-and-forget), and **log**
everything to one rolling file. The magic that lets an agent track and execute — the same
door serves a user click and an MCP trigger. Generic, for all projects.

## The laws kept here

1. **ONE DOOR.** A user click and an agent's MCP call walk the SAME path; the log records
   who fired it (source: `user` · `agent` · `process` · `system`).
2. **FIRE-AND-FORGET + THE WRAP.** The caller never waits — the receipt answers at once —
   and the outcome lands later as its OWN event (`<name>.result` or `<name>.error`,
   linked by `of`). Nothing blocks; nothing is lost.
3. **SMALL BY DESIGN.** The log holds only events that DO something (~24 h, a byte
   ceiling, self-trimmed; nothing mousemove-class ever registers).
4. **GENERIC.** For all projects — no project words inside.

## Layout

```
public/ts/     TypeScript sources (one feature per file: header · interfaces · functions · runTests)
public/ts/browser/  browser-only sources (loaded by the page as native ES modules)
public/js/     compiled ES modules, one .js per .ts (esbuild)
public/index.html   the GUI page served at /
data/          default home of the event log at runtime (the file itself is ignored by git)
Event_Handler_module.js  THE ONE FILE LOADED by another code thread — the embed entry (createModule/startModule; expects a log path)
Docs/          the module docs — index.html (purpose + every .d.ts; the ONE file agents read) + index.css
scripts/       build-docs.cjs — regenerates Docs/ (`npm run docs`)
```

## Core Modules

| Module File | Reason / Functionality |
| :--- | :--- |
| `eventHandler.ts` | THE CORE: register (the palette), trigger (fire-and-forget), the wrap (outcome as its own event), watchers, counters, purge hand. |
| `logStore.ts` | The rolling JSONL file: append · read · tail · filter · atomic purge (retention + byte ceiling), self-trimmed on a timer. |
| `mcpTools.ts` | The AGENT face as a REGISTRY (list + call, MCP-shaped): `event_list` · `event_trigger` · `event_log` · `event_purge`. Same object on the module's /mcp and on Api_Root later. |
| `mcpServer.ts` | MCP over HTTP: JSON-RPC, sessions, tools/list + tools/call over any registry; plain JSON or SSE frames. |
| `apiServer.ts` | The HTTP face: /health · /api/events · trigger · log · purge · stream (SSE) · the MCP mount · static. Optional shared token. |
| `staticFiles.ts` | Serves `public/` on the same port — MIME map, index fallback, traversal guard (never escapes the root), a 404 that names the API. |
| `browser/gui.ts` | The page: the palette (fire any event) + the live log + filters + purge. Pure renderers (self-checked) + `mount()`. |
| `client.ts` | The ES-module client (fetch + one SSE reader) — the page imports the SAME client the tests use. |
| `main.ts` | The entry point: flags/environment → handler + API on a port; banner; signals. |
| `selftest.ts` | THE GATE: runs every module's own self-check in one command → 99 asserts; GREEN/RED; non-zero exit on failure. |
| `Event_Handler_module.js` | THE EMBED ENTRY: the one file another code thread loads — re-exports the surface and adds `createModule()` / `startModule()`; **expects a log path**. Its own check: `node Event_Handler_module.js`. |
| `Docs/index.html` | THE ONE FILE AGENTS READ: purpose + the `.d.ts` contract of every file. Generated by `scripts/build-docs.cjs` (`npm run docs`); `index.css` is style only. |

## Quick start

```bash
npm install                # esbuild, typescript, @types/node (dev only)
npm run build              # public/ts/**/*.ts → public/js/*.js
npm run typecheck          # tsc --noEmit (strict)
npm run selftest           # the gate: every module's own self-check → 99 asserts
npm run docs               # writes Docs/index.html (purpose + every .d.ts) and Docs/types/

npm start                  # GUI + API + MCP on http://127.0.0.1:8126
                           #   GUI  http://127.0.0.1:8126/
                           #   API  /api/events …
                           #   MCP  POST /mcp
node Event_Handler_module.js   # the embed entry's own check
```

Flags (also readable from the environment as `EH_PORT`, `EH_HOST`, `EH_TOKEN`, `EH_LOG`,
`EH_RETENTION_HOURS`, `EH_MAX_BYTES`; a flag beats the environment):

| Flag | Default | Meaning |
| :--- | :--- | :--- |
| `--port` | `8126` | API port (`0` asks the OS for a free one) |
| `--host` | `127.0.0.1` | bind interface — **local unless you say otherwise** |
| `--token` | *(none)* | shared secret; then `/api/*` and `/mcp` need `x-eh-token` or `?token=` |
| `--log` | `./data/events.log` | **THE path** — where events are logged (one rolling file) |
| `--retention-hours` | `24` | keep events younger than this; the rest is trimmed |
| `--max-bytes` | `8000000` | byte ceiling — oldest lines go first |

There is no `data.yaml`: nothing authored to persist here. The record belongs to the host —
it lives at the path the host passes.

## API

| Method + path | What it does |
| :--- | :--- |
| `GET /health` | liveness + counts (events, log lines, bytes) |
| `GET /api/events` | the palette: every registered event + its counters |
| `POST /api/events/trigger` | fire `{name, payload?, source?}` (source defaults to `user`; MCP defaults to `agent`) |
| `GET /api/events/log?limit=&sinceHours=&name=&source=` | read the record (tail + filters) |
| `POST /api/events/purge` | trim on demand (retention + byte ceiling) |
| `GET /api/events/stream` | the live feed (server-sent events: `ready`, then one `event` frame per line) |
| `POST /mcp` | the agent door (MCP over HTTP) |
| `GET /` | the GUI |

Errors are always `{error:{code,message}}` with a real code: `bad_json`, `no_such_event`,
`unauthorized`, `no_route`.

```bash
curl -s -X POST localhost:8126/api/events/trigger \
     -H 'content-type: application/json' -d '{"name":"demo"}'
curl -s 'localhost:8126/api/events/log?name=demo.result'      # read the outcome
curl -N localhost:8126/api/events/stream                      # live feed (SSE)
```

## The MCP endpoint (for agents)

The registry (list + call) is the same object the module's own `/mcp` serves — mount it
elsewhere (Api_Root, tomorrow) and nothing drifts:

- `event_list` — THE PALETTE: what's registered, therefore fireable.
- `event_trigger` — fire it. Fire-and-forget; the outcome is a later event.
- `event_log` — read the record (tail, filter by name/source).
- `event_purge` — trim on demand.

```bash
curl -s -X POST localhost:8126/mcp -H 'content-type: application/json' -d '{
  "jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","clientInfo":{"name":"curl","version":"1"}}}'
curl -s -X POST localhost:8126/mcp -H 'content-type: application/json' -d '{
  "jsonrpc":"2.0","id":3,"method":"tools/call",
  "params":{"name":"event_trigger","arguments":{"name":"demo"}}}'
```

## Using it as a module (ES) — and the embed entry

```js
// the one file another code thread loads — it EXPECTS A LOG PATH:
import { createModule, startModule } from './Event_Handler_module.js';

const m = createModule({ logPath: 'C:/somewhere/events.log' });   // pieces in THIS thread
m.handler.register('door.open', (payload) => ({ opened: true }));
m.handler.trigger('door.open', { by: 'user' }, { source: 'user' });
// … later, the outcome is its own event: m.handler.read({ name: 'door.open.result' })

const s = await startModule({ logPath: 'C:/somewhere/events.log', port: 0 }); // its own door
console.log(s.url);           // http://127.0.0.1:<port>
await s.stop();
```

## Notes that will bite otherwise

- **Trigger answers a receipt, never an outcome** — the outcome is a later event; poll
  `event_log`/`read()` for `<name>.result` / `<name>.error`.
- **Names**: letters/digits/`._-`/spaces (phrases welcome — e.g. `add Process Console Display`); `<name>.result` and `<name>.error` are reserved.
- **The log self-trims** — a timer runs the purge; `event_purge` is the manual hand. A
  trigger of an unknown event is refused with `no_such_event` and is NOT logged (it did
  nothing).
- **A watcher that throws never breaks the record** (and a broken disk never breaks a
  caller — the record is fail-soft).

## Self-check

```
npm test        # build → typecheck → the gate (99 asserts, exits non-zero if any fail)
```

Every module ends with its own `runTests()` (kept, commented out of the module body) and
the gate collects them, per module, in one report. The checks spawn real servers on real
ephemeral ports, write real files and make real HTTP calls — nothing here is a mock. The
GUI's DOM half is verified against the live page (the ids the module wires are the ones
`public/index.html` carries, and the gate asserts they are all there).
