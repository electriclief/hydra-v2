Join

the shelf's self-description and resolver · door on :8131 · wired at boot · names only, carries no traffic

Join answers one question about this box: what is here, and where does it answer? It reads the join.json each module writes about itself, probes the ports those files claim, and keeps two columns that never merge — should (what the files say) and is (what answered just now). Its one act is resolution: asked for something declared but not answering, it asks ProcessWrapper to start it and answers starting, so a lookup never says "not found" when the truth is "not started yet".

How it holds together

A declaration is five facts, and the module writes them itself. name, kind, port, start, wiredAtBoot come out of join.json; one human sentence (what) may come from package.json and from nowhere else. Join never guesses an identity. A fact that is absent stays visible in the row's missing list, and a module with no join.json at all is still listed — inferred, with kind: "door", port: null and its gaps named. A folder name is never turned into a port.

The kind decides what a thing is allowed to claim. There are eleven built-ins — door, shell, catalog, service, agent, app, tool, plugin, mcp, node, storage — and any extra lives in Join/data/kinds.json, merged on load with no code change. A kind answers only two questions: may it have a port, and does it have a start command. So an Electron_Wrapper that declares a port has it refused, and the refusal is recorded in that fact's sources entry rather than silently dropped. An unknown kind is accepted as declared and marked kindKnown: false, because the shelf grows by adding things, not by editing the resolver.

Two columns, because "declared" and "answering" are different facts. A probe is GET http://127.0.0.1:<port>/health with a 1500 ms deadline, and a 200 or a 404 counts as answering — a 404 still means something is listening and speaking the door's dialect. The liveness vocabulary is up, down, starting, offered, absent. A declared-but-dead module keeps its should.port and reads is: "down" with a detail that says "declared on 8130, not answering". Nothing is cached as a green tick.

The lazy load goes through ProcessWrapper, never through a spawn. Join itself starts nothing. It posts /api/events/trigger to http://127.0.0.1:8125 with the event add Process Console Display and a payload of {name: "console-<module>", command, cwd}, expects HTTP 202, and then says so honestly: a 202 is fire-and-forget, so the reason line reads "asked ProcessWrapper to start it" rather than claiming the process is up. With --dry or JOIN_DRY=1 it still answers starting but the reason says it was told not to start anything. There is exactly one place a process can live, and Join is not it.

A member is a thing with no folder. A remote node, an MCP door, a share, an app on another machine: those are joined, not installed, so they are registered into Join/data/members.json — a single JSON file written atomically (temp file, then rename). The stored record carries name, kind, port, url, start, what, probe, deps, provides, tags, meta, registeredAt, updatedAt, and it becomes a Declaration with origin: "registered", so the resolver needs no second code path. A registered row beats a file row of the same name: an explicit runtime registration is a later, more deliberate statement than a file on disk.

Order comes from declared deps, and the hard cases are named. /api/plan runs Kahn's algorithm over deps[]. A dependency on something not on the shelf is reported under blocked with the missing name; a loop is reported under cycles. Neither is silently smoothed over, and neither prevents the rest of the order from being useful.

The door has one face for two audiences. A person gets the page at /; an agent gets POST /mcp speaking JSON-RPC (initialize, tools/list, tools/call, SSE framing when the caller asks for text/event-stream). The guard, when a token is configured, covers /api/* and /mcp only — static files stay open so the operator can load the page. With no token the door trusts loopback, and it binds 127.0.0.1 by default.
