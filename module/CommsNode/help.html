CommsNode

door on port 8160

One node that can hear, see and speak, assembled from four small doors. The hub holds the sequence and the state, never the hardware: it asks AudioIn, VideoIn, AudioOut and WakeWord what they have, runs trigger-capture-transcribe-answer-speak, and says which door is down when one is.

Concepts

Doors, not devices

AudioIn, VideoIn, AudioOut and WakeWord each own one device and can fail alone. The hub asks each for its inventory on demand and says which one is down instead of hiding the gap.

The loop

wake -> POST /api/wake -> capture N seconds -> transcribe -> optional agent -> speak the answer. Each step is an HTTP call to a door, so a step can be swapped for another node's door by changing one URL.

Typed absence

A missing microphone is no_mic with the devices that were enumerated; a missing STT is stt_missing with the path it looked for. Nothing returns silence and calls it success.

Published fact

node..comms carries the four door URLs, the capture length, the STT engine and the last exchange, refreshed every 30 s with a 120 s TTL so a dead node stops advertising.
