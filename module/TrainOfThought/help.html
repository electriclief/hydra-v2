TrainOfThought

the long-term intention DAG · door on :8135 · not wired at boot · answers "what is next" from the frontier, not a clock

TrainOfThought holds the work that outlives a session: one node per intention, carrying why it exists, what it waits on, the ordered actions left, and an append-only trail of who touched it. /api/next reads the DAG and hands back the node that is actually takeable now — active, unclaimed, with every dependency closed and an action written down. Closing a node archives it with the one sentence that says why. It is not a job log: a scheduler run or an image render creates no node here.

How it holds together

A thought is a node in a DAG, not a row in a list. The store is one plain JSON file, data/thoughts.json, shaped {version: 1, nodes: []}, written atomically (temp file, then rename) and re-read before every mutation because it is meant to be hand-editable while the door is running. A node is ref (8 hex, minted at random and re-minted on collision), title, intent (prose — why this exists and what "done" looks like, never an enum), state, deps[], next[], tags[], trail[], created, touched, and optionally closed{at, summary, sessionRefs[]} and claimed{by, at, expiresAt}.

Edges point one way: a dep is something this node waits on. deps[] holds incoming edges, so the graph reads "when 294cd029 is done, 954deebc becomes takeable", not the reverse. Linking a dep that is missing is refused by name; so is an edge that would close a loop, checked by walking ancestors upward from the proposed dep. The write is refused rather than quietly producing a graph that can never finish.

Readiness is a conjunction of four facts, and none of them is a date.

is it ready?the rule in dag.ts
stateactive — parked, blocked and done never surface
leaseno claim with expiresAt > now — a live seat is someone else working
actionnext.length > 0 — an intention with no next step is a note, not work
depsevery ref in deps[] exists and is done

The frontier is those nodes sorted by touched oldest first, so the thing that has waited longest is offered first. When the frontier is empty, /api/next does not answer a bare "nothing": it returns why, a set of disjoint counts — claimed, notActive, noAction, waitingOnDeps, ready — which names the wall instead of implying there is no work.

The trail is the memory, and it is append-only. Each entry is {at, kind, text, by, sessionRef?} with kind one of session · note · decision · event · claim · state. by is never empty — an agent name, user, or system — because provenance is the point. Nothing rewrites an old line, including a closure: close sets state: "done", writes closed, and appends "closed — <summary>". The summary is required (at least 8 characters) and setting state=done directly is refused with use_close: the sentence is the only thing an archive is for.

A claim is a lease with an expiry, not a lock. Parallel agents take a seat with POST /api/thoughts/<ref>/claim {by, minutes?} (30 minutes by default; login takes 240). A live claim is a refusal carrying the holder and the expiry, never a silent overwrite. Expired seats are reaped and the trail says seat expired (was <name>) by system, so a crashed agent cannot hold a train forever. /api/seats is the straight answer to "who is working on what".

The brief is a file, so it survives every door being down. On every save, frontier.ts regenerates data/frontier.md and data/frontier.json: what to take up, what is stuck and why, counts per state, and the store it came from. It is rewritten in the same save as the store, so it can never describe a node that has already moved — a stale brief is worse than none, because it would send a session at work that is closed. node public/js/frontier.js --data <dir> prints it with no server; a whole session can start from cat data/frontier.md.

Every thought owns a folder from the moment it exists. data/thoughts/<ref>/ is created at add, because an intention with nowhere to put its output ends up with its output in the wrong place six weeks later. Existing artifacts are attached, never copied: symlink first, then hard link, then a *.pointer.txt holding the absolute path, and the mode used is returned because "linked" and "copied" are not the same claim.

SessionDiary is lazy, by ref, over HTTP only. Nothing here imports its code. A trail entry carries a plain 8-hex sessionRef, so the evidence outlives the dependency; sessionClient.ts turns those refs into titles and goals only while :8134 answers, with a 15-second probe cache and a 1200 ms timeout. When the diary is down every card resolves to {ok:false, reason} and nothing throws — the DAG, the frontier and the archive stay fully usable. The link is written the other way round too: at session start, scripts/session-start.mjs --take a,b appends one line to SessionDiary/data/session-links.jsonl and posts the same fact to POST /api/thoughts/<ref>/trail when the door happens to be up. The door itself never writes the links file.

The cycle seam is optional and nothing depends on it. POST /api/cycle/tick records what a caller (a future Phoenix cycle) saw, idempotently per cycle number, and reports sessions that are attached to no train as warnings rather than ignoring them. If no cycle ever lands, nothing here runs and the frontier alone answers "what is next".
