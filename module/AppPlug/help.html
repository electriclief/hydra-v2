AppPlug

one app, one namespace · door on :8156 · a manifest per app

AppPlug is the plug for programs that only know how to print. It runs the app, reads its console, turns the lines a manifest names into paths, and publishes one link into State — foo_bar -> http://127.0.0.1:8156. From then on the LAN asks foo_bar.progress and gets the app's own live number, with the moment it was seen, without the app knowing Hydra exists.

Three rules that keep it honest

rulewhat it prevents
freshness travels: every value carries at; silence past staleMs answers {ok:false, why:'stale'}last week's percentage presented as live
death is typed: an exited app answers gone with its exit code 0 % — which reads as "the work reset" instead of "the work ended"
the namespace is locked: a second adapter for a namespace a live one holds refuses to start two answers for one name, and a node claiming progress for an app it is not running

The adapter also owns its child: kill the adapter and the app goes with it, so nothing is ever left running that the ProcessWrapper table cannot see.

The manifest is the plug

{
  "app": "foo_bar",
  "namespace": "foo_bar",
  "command": "C:/Path/To/foo_bar.exe",
  "args": ["--steps", "100"],
  "adapter": {
    "kind": "console",
    "staleMs": 5000,
    "patterns": [
      { "match": "^work:\\s*(?<pct>\\d+)%", "paths": { "progress": "pct" } },
      { "match": "^phase:\\s*(?<phase>.+)$", "paths": { "phase": "phase" } }
    ]
  }
}

A pattern maps a named group to a path ({"progress": "pct"}), a match position to a path ({"code": 1}), or several groups at once. Every adapter also gets line, lines, and a status object, whether or not the manifest asks for them.
