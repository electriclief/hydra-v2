ProcessWrapper

Module docs — the ONE file. Purpose + the contract (.d.ts) of every file. Generated by npm run docs — edit the sources, not this file.

Purpose

ProcessWrapper takes a process command (foo.exe, "python bar.py", a bare executable), launches it as a child process, captures its output as a text stream, and serves a GUI, an HTTP API and an MCP endpoint that can launch new processes, hand out a copy of a process's output, write to its stdin, and kill it.

Two laws are kept here. ONE LIFE = ONE FILE: every process life gets its own append-only text file under data/streams/ — never rotated, whole while the process is alive, kept at death until an operator deletes it. The RAM buffer is a convenience for fast copies; the file is the ground truth. NOTHING HIDDEN: a child process only ever comes from processWrapper.launch(), and every child is in the table with its id, pid, life, exit code and stream file.

Embed it: the ONE FILE another code thread loads is ProcessWrapper_module.js at the module root — it re-exports the whole surface (table, hub, API, client, registry) and adds createModule() (pieces in the host thread, no port) and startModule() (the module's own little door on a port). npm start is different: it stands this module up as its own local thread.

Run it

npm test          # the gate: build → typecheck → selftest
npm start         # GUI + API + MCP on http://127.0.0.1:8125
npm run cli -- help      # the pw terminal face
node ProcessWrapper_module.js   # the embed entry's own check

/**
 * @module apiServer
 * @description The HTTP face of the wrapper: launch a process, read or follow a copy of
 *              its output stream, write to its stdin, list it, kill it.
 * @intent A wrapper that can only be used from the process that owns it is a library, not
 *         a wrapper. This module puts the process table on a port so any surface — a page,
 *         a script, another Hydra node, curl — can start a command and take its own copy of
 *         the output as a text stream (whole, ranged, or live over SSE), and can kill what
 *         it started. No dependencies: node:http, one file, every route self-checked.
 *
 * Routes (all JSON unless noted):
 *   GET    /health                          → liveness + counters
 *   GET    /api/processes                   → the table (?life=&tag=)
 *   POST   /api/processes                   → launch {command|saved, args, cwd, env, name, tag, shell}
 *   GET    /api/processes/:id               → one record
 *   GET    /api/processes/:id/output        → a COPY of the text (?from=&limit=&channel=) text/plain
 *   GET    /api/processes/:id/stream        → a LIVE copy, SSE (?from=&channel=)
 *   GET    /api/processes/:id/file          → where the ground-truth stream file is
 *   POST   /api/processes/:id/input         → write to stdin {text}
 *   POST   /api/processes/:id/kill          → kill {force, graceMs}
 *   DELETE /api/processes/:id               → kill + drop the record
 *   GET    /api/commands                    → saved commands (data.yaml)
 *   POST   /api/commands                    → save one
 *   DELETE /api/commands/:name              → drop one
 */

    channel: StreamChannel;
    text: string;
    at: number;

    from: number;

     * interleaved) — the same frame `output(id, {from})` uses for the 'both' copy. Offsets
     * are per-frame on purpose: a copy asked to start at N must skip the text before N in the
     * frame it was asked about, whether that text already exists or arrives later.

    fileFrom: number;
