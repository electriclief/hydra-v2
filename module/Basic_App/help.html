Basic_App

the shell — one window, every door, and the level you are shown

Basic_App is the Electron shell that turns a shelf of module servers into one application window. It starts or adopts every door, mounts the window through Electron_Wrapper, serves the small shelf API on port 8130, and owns the settings that decide which tabs a person is shown. It is the only process on a node that is allowed to know the whole door table, because it is the only one that has to start the rest.

How it holds together

A door is a module that listens on a port. The shell's job is to make sure each one is listening, and to keep its hands off the ones that already are: DOOR_TABLE is the list, and each row says what to launch (dir), where it should end up (port), which entry file to run when it is not the default (script), and any argv flags the module wants (args, e.g. SessionDiary --scan 120). Before launching, the shell probes the port; a door that answers is adopted, not duplicated. That single rule is why a window can be closed and reopened without the LAN losing its services for ten seconds.

The processes themselves are not children of the window. They are booked through ProcessWrapper on :8125 and appear there as tabs tagged basic-gui, so closing the window is a presentation choice and the doors keep running until something explicitly pops them.

Tabs are data, not code. electron/ui.cjs holds a catalog: for each tab, its name, the address it points at, a group, and the module folder whose help page documents it. The catalog is filtered by a user level kept in electron/ui.json:

  • basic — the Menu only, for someone who does not want tabs to choose between.
  • advanced — Menu plus the Memory sub-modules (Diaries, Thoughts).
  • development — every tab, including the doors themselves.

Any single tab can be ticked on or off in View, and an explicit tick beats the level in both directions: unticking Mirror in Development hides it, ticking Join in Basic shows it. The tick lives in the same file, so the window comes back the way it was left.

Rebuilding the menu bar from inside the click of an item that lives on that bar is how Electron dies on Windows. Every settings change therefore lands on a 60 ms timer, after the click has returned, and only one rebuild can be queued.

The third job is documentation. The shell starts a small static server (8199 by default, an ephemeral port if that one is taken) which serves each module's own help.html and an index that marks a missing page as missing. The Help menu opens it as a tab, so the docs are a view of the same window rather than a folder somebody has to find.

The shelf API is loopback-only on purpose. It is the console in front of this machine's own doors, not a service the LAN is meant to call; what the LAN talks to is Core and Mirror.
