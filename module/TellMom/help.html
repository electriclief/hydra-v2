Tell Mom

one verb for telling the operator · door on :8139 · a declaration per sender, a mute per subject, a receipt per tell

Every module eventually has something to say to the operator, and the worst way to say it is a transport of its own: five modules, five tokens, five loops that can page a phone at 3am. This door owns the one verb — tell — the policy that governs it, and the receipt that proves what happened. A caller names itself, says what it wants to say, and gets back a verdict: sent to which channels, or muted for which reason. Nothing is ever silently dropped, because the whole point of a receipt is that "I told the operator" and "nothing happened" are different sentences.

No Telegram. The operator does not want it and there is no adapter for it here. Discord is the phone channel because this rig already has a token — used outbound only: one HTTPS POST per message, no gateway, nothing that stays connected between messages.

The policy is a file, and a hand edit lands on the next request

data/policy.json is stat-ed on every tell and reloaded when its mtime moves, so "I muted that subject" becomes true the moment the file is saved. A policy cached until restart would leave the operator arguing with a door that cannot hear them.

sendersa declaration per module: {"phoenix": {"perHour": 4}}. perHour 0 = this module may not tell at all (403, with the reason). A severities list caps what it may send.
mutedSubjectssubject prefixes the operator has silenced. "Phoenix upkeep" mutes that subject while the module still tells others; "*" mutes everything. Alerts do not cross a mute — the operator's word outranks the severity.

Why a sender declaration, not a rate limit alone

A runaway loop is not a policy problem until the module has a name. Once it does, the loop's own declaration is the throttle: four an hour is four an hour no matter how often the beat fires, and a module that should never page is declared at zero rather than trusted to behave.

Receipts, not silence

Every tell is written to data/told.jsonl whether or not a transport took it — including refusals, with the reason: subject muted by policy (…), sender 'x' ceiling reached (2/4 this hour), same dedupeKey told 1x inside 900s, quiet hours. The same verdict is republished to State as node.<ref>.told with by, reachedSomething and count1h, so the LAN row shows a tell that reached nobody instead of burying it in a log. A channel that is not configured fails naming the exact variable it wants.

Phoenix is the first client: a beat that fails an entry calls this door with by: "phoenix" and the dedupe key phoenix.upkeep.failed, so a red beat is one message and not a stream of them. The inbound side — reading Discord messages, brokering node-to-node traffic through double NAT — belongs to a broker module that owns that one connection; Tell Mom stays a sender.
