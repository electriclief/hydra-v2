So whatever that installer erased, **it wasn't this disk.** Mint went somewhere else — one of three places:

1. **The machine's internal disk.** Most likely. If that box has its own drive, "erase disk" took that one.
2. **The Ventoy stick itself.** This happens more than people admit — booting from the stick, the installer offers the stick as a target and it gets picked. Everything "works," and the machine it runs on has nothing.
3. **Nowhere** — if it never reached the end, a half-written ESP plus no root.

Here's the ten-second way to know. From that machine, booted into the Mint live session (or the installed system if it boots):

lsblk -o NAME,SIZE,MODEL,FSTYPE,LABEL,MOUNTPOINT

What the output means:

- **ext4 on an internal disk, and that disk has an `EFI` partition** → Mint is installed. It just isn't first in the boot order. `sudo efibootmgr -v` will list an `ubuntu` entry and I fix it with one command.
- **ext4 on the USB device** → you installed onto the stick. The machine is still Windows; nothing else changed.
- **No ext4 anywhere** → the install didn't complete, and the "took forever" was the network update phase before it stalled.
