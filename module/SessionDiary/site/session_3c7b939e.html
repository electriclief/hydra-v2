- **openbmb/MiniCPM-V-4.7-1B + `-gguf`** — *HF Trending Models (created 2026-10-06, still climbing; official GGUF updated today, 26.6k dl, 69 likes on the GGUF, 359 likes on base)* — A 1B on-device multimodal model with image + video understanding and an official llama.cpp GGUF from the org itself: the only new VLM this cycle that runs entirely inside the GTX 1660's 6 GB (or pure CPU) with room to spare.
- **prism-ml/Ternary-Bonsai-2-27B-gguf** — *HF Trending Models (top-trending GGUF, 4.85M dl, 2,699 likes; released 2026-09-16, still #1 in the GGUF slice)* — Ternary 1.58-bit 27B: **5.95 GB** deployed (PTQ1_0) or 7.21 GB (PQ2_0) vs ~54 GB FP16, retaining 98.2% of FP16 intelligence — the first 27B-class reasoning model that plausibly fits the 1660 at 6 GB, and trivially the RX 6800.
- **LiquidAI/LFM2.5-24B-A2B + `-GGUF`** — *HF Trending Models (created 2026-10-12/13, 380 + 165 likes, official quants published)* — 24B MoE with only ~2B active params and first-party llama.cpp GGUFs, so decode cost stays laptop-class and partial CPU/GPU offload is viable on 6 GB.
- **AMD-targeted quant family: `julianmb/Qwen-3.8-27B-ROCmFP4-FAST-GGUF`, `kingjones777/*-ROCmFP4-STRIX-MTP-GGUF`, toolchain `charlie12345/ROCmFPX`** — *HF Trending Models (ROCm-tag slice; 13.4k / 6.9k dl)* — The only quantization line explicitly built for Radeon/wgfx (`gfx1151` + discrete Radeon): Qwen3.8-27B at **13.55 GiB ≈ 14.2 GiB with 8K context — fits the RX 6800's 16 GB**, ~30–36 tok/s with MTP speculation; most relevant single item for the AMD card this cycle.
- **ISTA-DASLab/Qwen3.8-27B-GSQ-RCO-GGUF** — *HF Trending Models (1.44M dl, 2,211 likes; arXiv 2605.00649 + IST-DASLab/RCO code)* — Per-tensor mixed-precision GGUFs (IQ2_XS **8.4 GB**, IQ3_XXS **10.1 GB**, IQ3_S 11.8 GB "task-lossless") — the best quality-per-byte option that lands *between* the 1660's ceiling and the RX 6800's 16 GB.
- **openbmb/MiniCPM-V-4.7-35B-A3B + official `-gguf` / AWQ / GPTQ** — *HF Trending Models (786 likes base, 100.8k dl on the GGUF, all touched 2026-10-15)* — 3B-active MoE VLM with first-party 4-bit builds: the largest new multimodal model that still fits the RX 6800 without splitting across cards.
- **Cloudflare/clef** — *HF Trending Models (#14 trending, 2,178 likes, Apache-2.0)* — 27B Qwen3.8-based decision model that answers every typed question in **one forward pass, no free-form generation**, so KV growth is bounded — unusually cheap to keep resident on a 16 GB card at low-bit quant.
- **Cactus-Compute/whistle** — *HF Trending Models (38.8k dl, 415 likes, updated 2026-10-10)* — Whole ASR model ships as a single **16.9 MB** quantized file running CPU-only with no GPU dependency, offloading speech work that would otherwise eat 1660 VRAM.

**Papers (HF Daily Papers)**

- **Joint Subspace Sparse Attention (JSSA)** — *Daily Papers, 9 upvotes, 2026-10-13* — Token-level sparse attention that directly cuts KV-cache decode traffic: the exact bottleneck that limits long context on 6–16 GB cards.
- **Your Transformer Is Secretly Elastic** — *Daily Papers, 3 upvotes, 2026-10-14* — Retraining-free elastic scaling of one pretrained checkpoint across a continuum of compute budgets — i.e. a single model that runs degraded on the 1660 and full on the RX 6800.
- **History Replays Itself (NoteBank, linear attention)** — *Daily Papers, 9 upvotes, 2026-10-11* — Decouples long-context memory from the recurrent state via a sparse episodic memory bank, promising long context at fixed inference memory.
