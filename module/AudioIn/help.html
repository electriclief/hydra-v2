AudioIn

door on port 8161

Records the microphone for N seconds and returns 16 kHz mono WAV plus the RMS and peak measured from the samples, so a muted device reads silent instead of looking like a working one. ffmpeg is spawned per request and exits; no device is held between calls.

Concepts

Level is measured, not assumed

RMS and peak are computed from the PCM samples in the file that was written. A capture below 0.0005 RMS is reported as silent, not as a successful recording of nothing.

ffmpeg is the whole audio API

One static binary enumerates DirectShow devices, captures, resamples and encodes. No native npm module, no python, no driver.

Nothing resident

There is no long-lived capture process: each request is one child that exits. A door that holds the microphone open blocks every other app on the machine.

    Wiring
  • needs: ffmpeg.exe (comms.ffmpeg)
  • gives: GET /api/devices, GET /api/level, POST /api/capture, GET /api/audio?seconds=N (wav)
