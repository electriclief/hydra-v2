State to File

the snapshot writer · door on :8151 · one file per writing node

State is memory-only on purpose: it boots blank, holds what it is handed, and a registration dies with its registrant. That is what makes the house easy to reason about — and it is also why a cold boot with no peers answering has nothing to point at. This door is the answer to that and nothing more: it subscribes to the registry's change feed and keeps one file of what the registry said, so a node with an empty room can be handed its phone book back.

What the file is, and is not

it isit is not
a snapshot of names and their content, at one momenta database the registry reads at boot
replaceable: each write is tmp + rename, so a reader sees old or new, never halfappend-only history
signed: writtenBy, at, source, and each entry's updatedAtanonymous — a reader must be able to refuse something older than its owner

The feed is preferred and a poll is the fallback, both debounced: a registry that ticks every five seconds must not mean a disk write every five seconds. A registry that is not answering produces a typed failure (unreachable/timeout) and leaves the last good file alone — an empty snapshot would be a lie about the LAN.
