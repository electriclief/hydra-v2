# API index — how to call a door without reading its source

`library/` holds two different promises and they must not be confused:

```
library/<service>/service.json   what this node can OFFER   (generated by scripts/export-library.mjs, hashed)
library/api-index.json           how to CALL what exists    (this file, written by hand, verified by use)
```

The first answers "can you run this model here". The second answers "what route do I hit, what does it return, what
does it cost, and who already calls it" — the thing that gets re-invented every time a new module needs the DAG, the
billboard, or the upkeep registry.

Query it:

```
python scripts/library.py list
python scripts/library.py show tot.brief
python scripts/library.py find billboard
```

## What earns an entry

1. **Callable from outside** — a door and a route, or a script with flags. Not "import this internal function".
2. **A stated cost** — bytes, milliseconds, one GET per minute. An unmeasured service is a guess with a URL.
3. **A real caller** — `used_by` names the code that calls it today. No callers means it is an idea, not an entry.
4. **Failure behaviour** — what it returns when the thing behind it is down. A silent empty answer is how an outage
   disguises itself as calm.

`scripts/library.py add` refuses an entry missing any of those fields, which is the only enforcement a catalogue
needs: it cannot rot into a wish list if it will not accept wishes.
