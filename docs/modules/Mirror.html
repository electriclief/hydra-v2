Mirror

the reader · door on :8137 · one LAN view · writes nothing, owns nothing

Mirror reads. On every tick it pulls a handful of known entry names from this node's State and from the State of every registry it is allowed to see, folds each set of answers into one node object, and serves the lot as a single LAN object — machine JSON, a markdown brief, and one route per node. It holds no truth and has no writes: stop it and every node keeps publishing, keeps working, and nothing anywhere is diminished by its absence.

How it holds together

A reader is defined by what it does not do. There is no lease, no heartbeat of its own, no cache of anyone's contents beyond the snapshot it is about to serve, and no route that changes another module's state. What it does keep between ticks is exactly one thing per peer: the last cycle number it saw and how many consecutive ticks failed to advance. That is the whole of its memory, and it is why killing Mirror is not an outage.

One registry's answers become one node. The grammar it reads is small and it is a grammar, not a discovery: node.<ref>.id, .doors, .cycle, .services.<slug> (plus a .services rollup index, if a node publishes one), .scheduler.booked.<jobId>, .resources.<name>, .health.<what>, .observed.<peer>. It pulls five of those names per node in parallel rather than running a discovery pass, because a reader that already knows the grammar pays five requests instead of a walk plus five. Anything else it receives lands in the node's unknown map — kept, not dropped, because an entry this reader cannot classify is a fact about the reader.

A 404 is an answer. Reachability is set by whether the far State replied at all, not by whether it had anything to say: a node that publishes no doors is up, just empty. Without that rule a freshly booted node would look dead for its first tick, and a quiet one would look dead forever.

Alive is a comparison, not a timestamp. Each peer's cycle counter is compared with the one from the previous tick: it went up, so the node is alive; it stood still while the door answered, or the door did not answer, so a miss is counted; twelve consecutive misses and the peer is gone. No clock is compared across machines, so a laptop with a dead CMOS battery ages exactly like a good one. The rules are a deliberate copy of Core's rather than an import across module folders — a runtime import that reaches into a sibling module is a deployment trap — and the copy is kept honest by a gate that imports both files and fails if they ever disagree. One honest quirk of those rules: the verdict reads stalled from the very first miss, and the three-tick threshold only changes the wording of reason; twelve is the number that turns it into gone.

No node rather than a false one. A peer that never answered assembles to null, but the view still emits a row for it carrying its ref, its verdict and its miss count and nothing else. A machine that disappears from the table is a machine nobody notices is gone, so the row stays and says so.

Self is not privileged. This node's own entries are pulled from its own State by the same five names as any peer, and assembled by the same function; the only difference is a role: "self" label and a verdict of alive once its own State answered. If that State is down, there is no self node at all — the LAN object then holds peers only and self: null, which is the truth rather than a placeholder. Every number in counts is a length of an array that is actually present; nothing is estimated, and schemaVersion is 1.

Wiring, for humans

What it needs to have something to read:

What it gives back:

givestoshape
GET /api/lan.jsona machine{schemaVersion, at, self, counts{nodes, alive, services, ready, booked}, nodes[]} — before the first tick, {ok:false, error:"no snapshot yet"}
GET /api/lan.mda person, or one agent callwho is up, what they offer, what is booked, what is degraded — no adjective without a number behind it

GET /healtha probe{ok, nodes, peers, at, refreshError, refreshes}
anything elsea stranger404 listing the four real paths

Two details that decide whether it can see a machine at all. It binds 0.0.0.0 and sends access-control-allow-origin: * with no token, because it is a read-only view of things already published on the LAN. And from Join it takes a member's ref as ref, name or id and its address as stateUrl, url, or an ip / host on :8127; a member registered with only a port yields no URL and is skipped, so a peer in Join needs a url to be read.

This is wiring in words, not a type. The exact shapes live in src/main.js, src/assemble.js and src/lan.js. If this page and the code disagree, the code is right and this page is a bug.
