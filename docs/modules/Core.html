Core

the basic server · door on :8136 · started by the app, one per node

Core is the part of a node that says who it is. On boot it registers this box's own subtree in its own State — what it is, what it answers on, and a heartbeat that never stops — then spends the rest of its life comparing that beat with the same beat arriving from every other node. It is the only thing here that writes about a node, and it writes only about the node it runs on.

How it holds together

A node is a tree, addressed by path: node.<ref>.<child>. Core does not invent a schema for the whole LAN; it publishes the few branches that a stranger would need, each as its own entry so a reader can take the cheap one:

entrywhat it answershow often it changes
node.<ref>.cycleam I alive, and since whenevery tick (5 s)
node.<ref>.idwhat this box is, its gpu, its paths, who it acts forrarely
node.<ref>.doorswhich ports answer right nowevery 12th tick
node.<ref>.services.<slug>one service, ready or noton change
node.<ref>.observed.<peer>what this node last saw of a peerevery tick, per peer

The cycle is the heartbeat, and it is a counter, not a clock. Nothing here compares timestamps across machines — a 2013 laptop's clock is irrelevant. A peer is alive if its number went up since the last look, stalled if the number stood still while the port answered, and gone if nothing answered at all. Three ticks before stalled, twelve before gone: enough that a closed lid is a nap, not an outage.

An observation is an opinion, and it lives under the observer. Core never writes into a peer's branch. When this node says observed.jims.verdict = stalled it is saying "I have not seen Jim's number move", not "Jim is broken". When Jim's own entry disagrees, that disagreement is a partition — information, not an error to reconcile away.

Nothing is stored twice. Core holds no mirror, no lease, and no expiry. A registration lives as long as the process that registered it, so a dead node's branch is simply not there: absence reads as absence, and the purge path that a push design would need does not exist because there is nothing to purge.

What leaves the node is a projection, not the tree. /api/broadcast answers the question a stranger is allowed to ask — who is this, is it alive, what can it make — and it is a filter over entries the node already published, so it cannot drift from what the node says about itself.
