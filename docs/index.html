Hydra V2 — help

Every door explains itself: what it owns, what it refuses, and how to read it from an agent. These are the same pages the app serves on :8199, copied here by scripts/build-docs-site.py so they cannot drift.

Hydra V2 is not working. This is a construction site: no installer, one node, hardcoded paths, no broker, and no authentication by design. The pages describe the design honestly, including the parts that do not exist yet.

The doors — what the window opens

  • Menu:8133The way in — a tree of every service this node can make, its advert beside the row, its inputs page on click, and one booking call to the Scheduler. Nothing runs here.
  • Services:8128The catalog door — one data file per service, served on 8128. It holds definitions and runs nothing itself.
  • Scheduler:8132The book of jobs — one at a time, queued, recorded, with a RUNNER seam. The runner today is a dummy: it executes nothing and says so, so the wiring is real before anything runs.
  • State:8127The generic retainer — register any object under a dotted-path name and pull it back. Where a node registers itself as a child.
  • Event_Handler:8126The generic event handler — register, trigger, log. ONE door for a user click and an agent's call, and the log records who fired it.
  • ProcessWrapper:8125THE ROOT — the only place a process may come from. Every launched thing lives in its one table.
  • Join:8131The shelf's SELF-DESCRIPTION and RESOLVER — should (files) and is (probed), kept apart. NAMES ONLY: it never carries traffic and never decides. Asked for something declared but not answering, it asks ProcessWrapper to start it and answers 'starting', so a lookup never reports 'not found' for something merely not running.
  • TrainOfThought:8135The long-term intention DAG — nodes carry intent, next actions, an append-only trail and a claim lease; /api/next answers 'what is next' from the frontier, not from a clock; closing a node archives it with the sentence that says why. Reads the session manager (:8134) lazily for evidence and works with it down. Never a job log: a Scheduler run or an image render creates no node.
  • SessionDiary:8134The Hermes session wrapper: reads state.db read-only, writes a local static diary site (file:// clickable), asks dead sessions questions through the deepseek agent, and forks or restarts a session. Static HTML for reading; the API for acting.
